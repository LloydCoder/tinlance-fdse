# FDSE Development Rules\n\n## Canonical local quality gates\n\nRun from the repository root:\n\n- `python -m pip install -e \".[test,quality,security]\"`\n- `python -m ruff format --check .`\n- `python -m ruff check .`\n- `python -m mypy`\n- `python -m pytest`\n- `python -m pip_audit`\n\nCI runs the same gates. A local pass is not evidence of CI success.\n\n## Change control\n\nUse: inspect → design → implement → test → security review → CI → review → merge\n\nKeep M0 narrowly scoped. Do not introduce a generic agent runtime, sandbox, authorization, approval, audit, memory, model gateway or unrestricted customer-code execution into FDSE.\n\n## Release truth\n\n- Implemented means code exists.\n- Tested means relevant tests pass.\n- Verified means repository evidence supports the acceptance criteria.\n- Merged means GitHub reports `merged_at` for the PR.\n- Green means required workflows have completed successfully for the exact evaluated commit.\n\nNever infer one state from another.\n
